= Development Environment

== Reference host

The first-class host is Linux/x86-64.

The reference development distribution is Debian 13 ("trixie").

Debian versions will evolve; avoid depending on an exact compiler minor version unless a
real compiler bug requires it.

== Debian packages

On a clean Debian 13 workstation:

[source,shell]
----
sudo apt update
sudo apt install \
  build-essential \
  clang \
  clang-format \
  clang-tidy \
  lld \
  llvm \
  cmake \
  ninja-build \
  ccache \
  gdb \
  git \
  pkg-config \
  python3 \
  python3-venv \
  python3-pip \
  asciidoctor \
  linux-perf \
  valgrind
----

`valgrind` is supplemental; sanitizers are the primary memory/UB debugging mechanism.

LLVM development libraries are not required until a JIT backend is actually started.
Do not add them to the core build merely because LLVM may be used later.

== Fast builds

`scripts/build-pgo.sh` builds `build/pgo/ultraviolent` with profile-guided and link-time
optimization, trained by running the user's IP27 PROM from power-on:

[source,shell]
----
ULTRAVIOLENT_IP27_PROM=assets/firmware/ip27prom.img scripts/build-pgo.sh
----

It needs Clang and `llvm-profdata`. Guest behavior is identical to `release`; on the
reference host it is about 1.6 times faster. The profile is derived from a proprietary
image and stays in `build/`. Use it for long boot runs; use `dev` and `release` for tests.

== Compiler policy

Clang is the primary compiler. The `dev`, `asan`, and `release` presets select `clang++`.

GCC is a required secondary compiler. The `gcc` preset builds the dev configuration with
`g++`. It becomes a CI gate once public CI is established.

Code that only compiles because of a Clang extension is a bug unless explicitly justified.

== Warnings

Development builds use aggressive warnings.

Treat project warnings as errors in CI.

Do not globally turn third-party warnings into errors if dependencies are added later.

== Formatting

`clang-format` defines mechanical formatting.

Do not mix large formatting churn with semantic changes.

== Static analysis

Use `clang-tidy` for selected checks that produce actionable results.

Do not enable hundreds of cosmetic checks that train contributors to ignore diagnostics.

== Profiling

Use Linux `perf` for low-level profiling.

Do not optimize until a profile identifies the bottleneck.

[source,shell]
----
perf stat -e cycles,instructions build/release/ultraviolent ...
perf record -e instructions -c 100000 build/release/ultraviolent ...
perf report --no-children --stdio
----

Sampling the `instructions` event shows where host instructions go per guest instruction;
the default `cycles` event also shows stalls. Start from a snapshot (`--load-state`) near
the code of interest. An optimization must leave the guest unchanged: compare console output
and a `--save-state` snapshot from before and after over the same cycle count; they must be
byte-identical.

To see the guest code behind a hot spot, histogram guest PCs with a short `--trace cpu` run,
translate the PC through the snapshot's TLB if it is mapped, and disassemble the bytes that
`tools/uvstate_memory.py` copies out of the snapshot.

For source-line attribution, configure a separate build with frame pointers and debug
information, and profile the benchmark workloads' commands:

[source,shell]
----
cmake -S . -B build/prof -G Ninja -DCMAKE_CXX_COMPILER=clang++ -DCMAKE_BUILD_TYPE=Release \
    -DBUILD_TESTING=OFF "-DCMAKE_CXX_FLAGS=-g -fno-omit-frame-pointer"
cmake --build build/prof --target ultraviolent
perf record -F 999 -g build/prof/ultraviolent ...
perf report --no-children --stdio -g none --sort srcline \
    --symbols 'ultraviolent::mips::Interpreter::run_until(unsigned long const&)'
----

== Benchmarks

`scripts/bench.py` times fixed guest workloads (`scripts/bench.py --help` lists them): a PROM
power-on, a cold boot of the installed disk to `login:`, and two workloads in a root shell
(user-mode arithmetic in awk; find and sum over system directories). Each workload ends at a
point the guest defines (a console `@stop`), so its guest cycle count and console output
are the same on every run and every build; only host time varies. The digest of the output
is the transparency check, and `--compare` fails if a digest changes.

The fixture is built once from an installed system after a clean shutdown (the
demonstration's work directory, for example) and holds copies of the user's private disk
and firmware state. It lives outside the repository, on local disk (default
`/var/tmp/ultraviolent-bench`):

[source,shell]
----
scripts/build-pgo.sh
scripts/bench.py fixture --from local/rc
scripts/bench.py run --save local/bench/base.json          # before a change
scripts/bench.py run --compare local/bench/base.json       # after: speedups, digests
scripts/bench.py run --repeat 1 cpu fs                     # a quick subset
----

The reported time is the best of `--repeat` runs, including process start and, for the
shell workloads, loading the 560 MB snapshot (under a second). Frequency scaling and other
load on the host add noise of a few percent; compare builds on an otherwise idle host.
Results are recorded in STATUS "Performance".

== Network development

RC-IP27 networking uses a Linux TAP backend.

Creating TAP/bridge interfaces may require root or appropriate capabilities. Keep the
network backend testable without root through synthetic packet injection.

Do not require privileged networking for ordinary unit tests.

== Host dependencies

Keep RC-IP27 runtime dependencies intentionally small.

The core should initially depend on the C++ standard library and host OS facilities.

Do not add LLVM, Vulkan, SDL, GUI frameworks, or large utility libraries before a milestone
requires them.

== Ccache

`cmake/Ccache.cmake` uses `ccache` as the compiler launcher when it is installed and its
cache directory is usable. A dangling cache directory (for example a broken symlink)
disables it at configure time, with a message.

A missing cache must never make the build fail; the build then uses the compiler directly.

Disable it with `-DULTRAVIOLENT_USE_CCACHE=OFF`. An explicit
`CMAKE_CXX_COMPILER_LAUNCHER` always takes precedence.
