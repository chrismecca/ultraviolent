* **Profile** (perf, `cpu` and `fs`): the interpreter is the time; devices barely register.
  Most of each guest instruction is work independent of its operands: the interrupt check,
  Count/Compare and Random bookkeeping, host-page validity checks, decode and nested
  dispatch, and a 32-byte `std::expected<Control, Exception>` returned through memory.
* **Done (transparent: digests unchanged, snapshots at the same cycle byte-identical to the
  baseline build's):** (1) the interrupt check, the translation context, the Count/Compare
  match cycle, and Random (derived from retirements) are kept up to date where their
  inputs change instead of recomputed per instruction; (2) the host page caches are
  flushed when translation or the bus mappings change (at the start of a run and after
  each bus access) instead of validated per access, and arming a watchpoint drops the data
  pages. Debug builds check both against the direct computation on every instruction.
  Result (best of 2, `--compare` against the baseline): `prom` 1.16x (64.9 M cycles/s),
  `boot` 1.23x (58.6), `cpu` 1.28x (57.6), `fs` 1.33x (73.7); a cold boot to `login:` now
  takes 280 s of host time instead of 345.
* **Tried and reverted:** keeping the bus byte order in `Cpu` instead of reading it through
  the bus made `fs` 13% slower in an A/B of profile-guided builds (layout, not the work
  saved). Run-to-run noise on this host is about 2.5%.
* **Performance objective** (with the user, 2026-09-28; IR.adoc "Performance objective"):
  first target at least the configured guest clock in guest cycles per host second on the
  representative workloads, 180 M cycles/s for the 180 MHz R10000, with benchmark digests
  and same-cycle snapshots unchanged. Tier 0 need not reach it alone; its measured result
  decides between more tier-0 overhead removal and tier 1 (JIT).
* **Designed and reviewed:** the Ultraviolent IR (doc/IR.adoc): decoded instructions and
  blocks for a tier-0 fast interpreter, later micro-operations for the JIT; exact
  per-cycle accounting, a mutable run limit rechecked at every boundary, slow bus paths as
  barriers, selective TLB invalidation, frame generations for code writes, and
  differential testing against the reference interpreter. Implemented in stages A-H (IR.adoc
  "Stages"); the user reviews after stage C.
* **Stage A done:** the rules in IR.adoc; boundary tests of the reference interpreter
  (`mips.run_until_limit_lowered_during_an_access`, `mips.interrupt_raised_during_an_access`,

  `Ip27Machine::synchronize_time` and tested by `ip27.events_run_at_cycle_boundaries`; the
  writable span contract on `AddressSpace::writable_memory_bytes`.
* **Stage B done (2026-09-29):** `decode` (a branchless lookup into one 240-entry table) and

== Known true

* The previous prototype demonstrated that original IP27 PROM execution is reachable with
  a software R10000/IP27 model.
* The prototype is a behavioral reference, not the architecture to copy mechanically.
* M0 core contracts (see `CORE.adoc`) are implemented and covered by 34 unit cases in
  `core_tests`: virtual time and clock-domain conversion, deterministic scheduler, typed
  addresses, byte order, RAM/ROM/MMIO address space, interrupt lines, reset kinds, tracing.
* Clang 19 and GCC 14 both build the tree warning-free with the project warning set; ASan and
  UBSan report nothing.
* The R10000 model (`MIPS.adoc`) implements the MIPS IV integer and FPU instruction sets,
  CP0, the 64-entry TLB, exceptions, interrupts, Count/Compare, LL/SC, watch, reset, and
  both byte orders, from the R10000 User's Manual v2.0 and MIPS IV ISA rev 3.2. Test
  encodings match GNU as for 173 instructions (`tools/check_mips_encodings.sh`).
* IP27 (`IP27.adoc`): the reset fetch reaches the flash at HSPEC `0x1fc00000`; the flash
  also appears at the base of LBOOT; the CPU's reset Config is the flash `ip27conf` mode word;
  CAC, UNCAC, and UALIAS reach memory; the Hub registers are at IALIAS. The PROM needs
  PI_CPU_NUM, PI_RT_COUNT, and the "Rst0" local-reset handshake.
* Mutation checks: deliberately broken endian lane selection, refill-vector selection,
  delay-slot EPC, XContext layout, FPU rounding mode, NaN sense, fused multiply-add,
  flush-to-zero, and sticky flags each fail at least one test.

== Known unknown

* partial-word bus transactions (uncached `SWL`/`SWR` and similar): not representable in
  `AddressSpace` yet; see `CORE.adoc`;
* the R10000 behaviors listed in `MIPS.adoc` "Hypothesis checklist";
* exact chosen CPU revision/reset fields;
* exact canonical IO6/XBOW widget mapping;
* exact firmware image expectations;
* reset defaults not explicitly documented;
* interrupt timing/order edge cases.

new file), the PROM reinitializes its environment and stops at its menu. There, `1` starts
the system, and `5` then `setenv AutoLoad Yes` makes later boots automatic. Other installed
disks: `irix-installed.img` is the disk as `inst` left it, before the first boot;
`irix-shut1.img` was shut down cleanly on the old topology.

Performance (2026-09-27, i5-3470T host, 300 M cycles from each snapshot and from power-on):
about 30 M instructions per second with the `release` preset and 45-55 M with the

transparent optimizations: TLB last-match cache, address-space last-hit cache, lazy time
