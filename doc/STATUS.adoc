= Project Status

Update this file at the end of every significant development session.

== Current milestone

M2 - Minimal IP27 reset machine (in progress)

* The unmodified user PROM executes from the reset vector. It passes its Config self-check,
  performs its Hub local-reset handshake, and reports LEDs 0x01 INITCPU and 0x02 TESTCP1.
  Deterministic; no PC-specific code. Specification: `IP27.adoc`.

* M1 - Reference R1x000 interpreter: deliverables implemented; `mips_tests` (77 cases) pass on
  every preset; no dependency on any machine (2026-09-24). Specification: `MIPS.adoc`.
* M0 - Clean core boots itself: deliverables implemented; acceptance commands pass on the
  reference Debian 13 host for the `dev`, `gcc`, `asan`, and `release` presets (2026-09-24).

== Canonical target

Minimal one-node IP27 / Origin 2000, defined in `IP27-TARGET.adoc`.

== RC-IP27 definition

Remote telnet login to an unmodified, installed IRIX guest.

== Known true

* The previous prototype demonstrated that original IP27 PROM execution is reachable with
  a software R10000/IP27 model.
* The prototype is a behavioral reference, not the architecture to copy mechanically.
* M0 core contracts (see `CORE.adoc`) are implemented and covered by 34 unit cases in
  `core_tests`: virtual time and clock-domain conversion, deterministic scheduler, typed
  addresses, byte order, RAM/ROM/MMIO address space, interrupt lines, reset kinds, tracing.
* Clang 19 and GCC 14 both build the tree warning-free with the project warning set; ASan and
  UBSan report nothing.
* The R10000 model (`MIPS.adoc`) implements the MIPS IV integer and FPU instruction sets,
  CP0, the 64-entry TLB, exceptions, interrupts, Count/Compare, LL/SC, watch, reset, and
  both byte orders, from the R10000 User's Manual v2.0 and MIPS IV ISA rev 3.2. Test
  encodings match GNU as for 173 instructions (`tools/check_mips_encodings.sh`).
* IP27 (`IP27.adoc`): the reset fetch reaches the flash at HSPEC `0x1fc00000`; the flash
  also appears at the base of LBOOT; the CPU's reset Config is the flash `ip27conf` mode word;
  CAC, UNCAC, and UALIAS reach memory; the Hub registers are at IALIAS. The PROM needs
  PI_CPU_NUM, PI_RT_COUNT, and the "Rst0" local-reset handshake.
* Mutation checks: deliberately broken endian lane selection, refill-vector selection,
  delay-slot EPC, XContext layout, FPU rounding mode, NaN sense, fused multiply-add,
  flush-to-zero, and sticky flags each fail at least one test.

== Known unknown

* partial-word bus transactions (uncached `SWL`/`SWR` and similar): not representable in
  `AddressSpace` yet; see `CORE.adoc`;
* the R10000 behaviors listed in `MIPS.adoc` "Hypothesis checklist";
* how the machine loop interleaves CPU cycles with scheduler events (M2);
* exact chosen CPU revision/reset fields;
* exact canonical IO6/XBOW widget mapping;
* exact firmware image expectations;
* reset defaults not explicitly documented;
* interrupt timing/order edge cases.

== Next task

Continue M2 with the observation loop in `IP27.adoc` "Observation log".

Current position: MD_MEMORY_CONFIG (`0x200018`), read right after LED `0x0e` SPEEDUP at 32 s
of virtual time. The PROM first spends 26 s timing out on its missing system controller
(ELSC), which it tolerates (IP27.adoc "Junk bus").

MD_MEMORY_CONFIG is the start of memory configuration (PRM LEDs `0x4a` MDIRINIT, `0x4b`
MDIRCONFIG "probe and configure memory size"). The IRIX-derived `sn0/hubmd.h` gives its field
layout, bank-size codes (MD_SIZE_*), and reset value (MMC_RESET_DEFAULTS). The PROM sizes
memory in software, so modeling it means making RAM decode depend on the programmed bank
sizes and on the installed DIMMs: memory placement becomes Hub MD behavior, not a fixed
window. Specify from `hubmd.h` and the PROM's observed accesses before implementing.

The evidence trail after memory, toward booting the CD: Hub II link, XBOW widget ID/status,
Bridge widget and PCI config, IOC3 PCI config and console UART, then the ISP1020 probe.
"Loading BASEIO prom" needs the user's `io6prom.img` behind Bridge (M3).

Loop mechanics: `ULTRAVIOLENT_IP27_PROM=assets/firmware/ip27prom.img
scripts/ip27-prom-checkpoint.sh`, `--trace hub,firmware,exception`, `--probe PC`. Record
evidence with its source class (`SOURCES.adoc`), model only the observed behavior, and add a
unit test.

Performance: about 12 M instructions per second (release). The TLB last-match cache and the
address-space last-hit cache were profile-driven and are transparent (callgrind). perf needs
`kernel.perf_event_paranoid` at or below 2.

Private assets are in the repository's `assets/` (firmware: `ip27prom.img`, `io6prom.img`,
`mmscfw.bin`; IRIX 6.5 and 6.5.30 media) and are ignored by Git. Two copies of the R10000
User's Manual are in `doc/*.pdf`, also ignored. The user-supplied PRM PDF is kept
outside the repository.

== Best known boot command

[source,shell]
----
cmake --build --preset dev
ULTRAVIOLENT_IP27_PROM=assets/firmware/ip27prom.img \
    scripts/ip27-prom-checkpoint.sh 2000000
----

Expected: LEDs through `0x4c` I2CINIT within 6 ms; `0x4d` I2CDONE at about 5.006 s; `0x0e`
SPEEDUP at about 32 s, then the MD_MEMORY_CONFIG stop. 32 s is about 5.8 G cycles, about 8
minutes with the release binary: `ULTRAVIOLENT_BINARY=build/release/ultraviolent`.
