== Source classes

Every cited fact names its source class. Classes are listed from strongest to weakest:

SGI hardware manual:: SGI or chip-vendor documentation of the hardware (for example the IP27
PROM Technical Reference Manual, the R10000 User's Manual). Supports `documented`.
IRIX-derived public header:: public source headers, mainly Linux `arch/mips/include/asm/sn/`,
that state they derive from IRIX headers (for example "Derived from IRIX
<sys/SN/SN0/hubio.h>, Revision 1.80"). They give SGI's own register names, offsets, and
field layouts, but not reset values or corner cases. Supports `inferred`, and counts as
strong evidence for layouts and encodings.
Public driver source:: other public drivers and emulators, read only for facts such as
register bits (for example Linux `i2c-algo-pcf.h` for the PCF8584). Supports `inferred`.
Observed PROM behavior:: what the user's unmodified firmware does when run: its accesses,
the values it tests, the paths it takes. This includes disassembly of the lawfully held
image to see which bits it examines. Supports `observed`.
Real hardware:: readings from a physical machine, for example POD register dumps. Supports
`observed` and confirms everything above.

When classes disagree, record the conflict and prefer the stronger class unless a real-hardware
observation settles it.

== Confidence labels

Use:

* `documented` — primary public documentation;
* `observed` — reproducible hardware/guest observation;
* `inferred` — strongest model consistent with evidence;
* `hypothesis` — not yet verified.

Code comments should not present `hypothesis` as `documented`.
