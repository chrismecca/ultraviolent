== CPU

In use (cited as UM and ISA in `MIPS.adoc` and in source comments):

* _MIPS R10000 Microprocessor User's Manual_, Version 2.0, January 29, 1997. Covers CP0,
  TLB, exceptions, address spaces, FPU implementation details, and the uncached attribute.
  Public copies are available from archive.org and SGI TechPubs mirrors.
* _MIPS IV Instruction Set_, Revision 3.2, September 1995, Charles Price. Covers
  instruction semantics and the FPU (appendix B).

Tool used as a cross-check, not as a semantic source:

* GNU as 2.44 (`binutils-mips64-linux-gnuabi64`, `-march=r10000`), to check the test
  assembler's instruction encodings (`tools/check_mips_encodings.sh`).

Use the most primary source available.

In use:

* Hub: Linux `arch/mips/include/asm/sn/sn0/hub*.h`, `asm/sn/addrs.h`, `asm/sn/intr.h`
  (IRIX-derived). Block-transfer engine sequence: Linux `arch/ia64/sn/kernel/bte.c` (SN1,
  public driver source).
* Xtalk widgets: Linux `arch/mips/include/asm/xtalk/xwidget.h` (IRIX-derived).
* XBOW: Linux v2.6.12 `arch/ia64/sn/include/xtalk/xbow.h` (IRIX-derived, "Copyright (C)
  1992-1997"; its structs describe byte-swizzled ia64 access, but its `#define` offsets are the
  hardware's).
* Flash PROM: AMD Am29F080 (PRM 2.3, chapter 5). The AMD datasheet is the reference for its
  command set when flash programming is modeled.
* PCF8584: Philips/NXP datasheet (`doc/PCF8584.pdf`, not committed) and Linux
  `i2c-algo-pcf.h`.
* System controller: Linux history tree (git.kernel.org tglx/history.git)
  `include/asm-ia64/sn/ksys/elsc.h` (v2.5.20) and `ksys/i2c.h` (v2.5.0), IRIX-derived. The
  same tree's `arch/ia64/sn/io/` has IRIX-derived xbow.c, xtalk.c, and pcibr.c (SN1 era),
  leads for M3.
* Serial EEPROM: 24C16 protocol (for example the Atmel AT24C16 datasheet).
* Bridge byte lanes and DMA: Linux v6.6 `arch/mips/include/asm/pci/bridge.h` (IRIX-derived:
  DEVICE bits, DIR_MAP, `PCI64_ATTR_*`), `arch/mips/pci/pci-xtalk-bridge.c` (DMA address
  form, SWAP_DIR use), `arch/mips/include/asm/mach-ip27/mangle-port.h` (I/O address
  swizzle), public driver source.
* IOC3: Linux v6.6 `arch/mips/include/asm/sn/ioc3.h` (`struct ioc3_uartregs`), and
  `drivers/tty/serial/8250/8250_ioc3.c` (register n at `offset ^ 3`).
* ISP1020: Linux v2.6.12 `drivers/scsi/qlogicisp.c` and `qlogicisp_asm.c` (register map,
  mailbox commands and parameter counts, handshake, IOCB layouts, firmware image format),
  public driver source; ISP1040 HCCR read bits from Linux `drivers/scsi/qla1280.h`.
* SCSI: ANSI X3.131-1994 (SCSI-2) for CDBs, INQUIRY, sense data, and mode pages.
* Local copies of these public files are in `local/sources/` (git-ignored).

== Source classes

Every cited fact names its source class. Classes are listed from strongest to weakest:

SGI hardware manual:: SGI or chip-vendor documentation of the hardware (for example the IP27
PROM Technical Reference Manual, the R10000 User's Manual). Supports `documented`.
IRIX-derived public header:: public source headers, mainly Linux `arch/mips/include/asm/sn/`,
that state they derive from IRIX headers (for example "Derived from IRIX
<sys/SN/SN0/hubio.h>, Revision 1.80"). They give SGI's own register names, offsets, and
field layouts, but not reset values or corner cases. Supports `inferred`, and counts as
strong evidence for layouts and encodings.
Public driver source:: other public drivers and emulators, read only for facts such as
register bits (for example Linux `i2c-algo-pcf.h` for the PCF8584). Supports `inferred`.
Observed PROM behavior:: what the user's unmodified firmware does when run: its accesses,
the values it tests, the paths it takes. This includes disassembly of the lawfully held
image to see which bits it examines. The same holds for the unmodified IRIX kernel the
emulated machine runs (the user's installation media, and slate's `/unix` for symbol
names): its accesses and the values it tests, read by probe and by disassembly of the
function concerned. Supports `observed`.
Real hardware:: readings from a physical machine, for example POD register dumps. Supports
`observed` and confirms everything above.

Not used without a user decision:: IRIX's own installed headers (`/usr/include/sys/SN/...`
from a real IRIX system). They are SGI-copyrighted and shipped with IRIX rather than secret,
but AGENTS.md restricts IRIX sources. The previous prototype cited them. Until the user
decides, use them only as leads, and confirm each fact from a class above.

When classes disagree, record the conflict and prefer the stronger class unless a real-hardware
observation settles it.

== Confidence labels

Use:

* `documented` — primary public documentation;
* `observed` — reproducible hardware/guest observation;
* `inferred` — strongest model consistent with evidence;
* `hypothesis` — not yet verified.

Code comments should not present `hypothesis` as `documented`.
