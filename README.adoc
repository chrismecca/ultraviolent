= Ultraviolent
:toc:
:toclevels: 2
:source-highlighter: highlight.js

Ultraviolent is a clean-room virtual hardware platform for SGI-class systems.

Its purpose is to run original, unmodified guest firmware and operating systems against
hardware-compatible machine personalities while allowing the implementation beneath
those interfaces to use modern CPUs, storage, networking, graphics APIs, or physical
hardware.

The first machine personality is an SGI Origin 200/2000-class IP27 system. Today it
installs unmodified IRIX 6.5.30 from its own discs with IRIX's own tools, boots it on one or
two R10000s (one runs faster than a real 180 MHz R10000 on a modest 2012 host, two about
as fast), keeps real time,
takes telnet and ssh logins over a virtual Ethernet, and shuts down cleanly when its
keyswitch is turned off. It has run for hours under load without a
fault (`doc/STATUS.adoc`).

Ultraviolent is not an IRIX port. It is not an application compatibility layer. It is not
a cycle-accurate R10000 simulator. It is a virtual machine whose contract is the
guest-visible hardware.

== Foundation

----
The guest changes as little as possible.
The future underneath it may change completely.

Machines own topology.
Devices own behavior.
Processor personalities own guest-visible CPU behavior.
The core owns execution mechanics.
Backends own host integration.
----

A physical SGI device may be represented by software today, a Vulkan backend tomorrow,
or an FPGA later. IRIX must continue to see the same hardware contract.

== What the machine has

* one IP27 node board (two with `--nodes 2`), each with one or two R10000 CPUs and 512 MB
  of memory by default
* Hub, Crossbow, and a BaseIO board: Bridge/PCI, two QL1040B SCSI controllers, IOC3 serial
  console and Fast Ethernet, the M48T35 timekeeper and NVRAM
* a SCSI system disk and CD-ROM drive, backed by files
* the flash PROM log and NVRAM kept in files between runs
* the module's system controller, far enough for its keyswitch to shut IRIX down and
  remove power
* original PROMs and unmodified IRIX, supplied by you

The reference interpreter is permanent. Decoded blocks (tier 0) and native x86-64 code
(tier 1, `doc/JIT.adoc`) run the same guest faster, and are tested against it.

== Quick start

You supply the PROM images and IRIX discs (`assets/README.adoc`); then, on Debian or Ubuntu
x86-64:

----
sudo apt install clang llvm cmake ninja-build python3
ULTRAVIOLENT_IP27_PROM=assets/firmware/ip27prom.img scripts/build-pgo.sh
python3 scripts/rc-ip27-demo.py --work local/vm     # installs IRIX: about half an hour
scripts/boot.sh local/vm                            # log in as root
----

`doc/USING.adoc` explains each step, the network, and the rest of everyday use.

== Build host

Linux/x86-64 is the first-class host. Debian GNU/Linux 13 is the reference development environment.
Other hosts may work later, but they must not distort the core design.

See `doc/DEVELOPMENT.adoc`.

== Private assets

No SGI firmware, IRIX installation media, installed disk image, NVRAM dump, or other
proprietary binary belongs in the public repository.

Ultraviolent accepts user-supplied paths to local assets. The recommended local layout is
documented in `assets/README.adoc`.

== Name

"Ultraviolent" is a deliberate play on the SGI color/optics lineage: IRIS, Indigo,
ultraviolet. The name is not intended to imply compatibility with or endorsement by SGI.
